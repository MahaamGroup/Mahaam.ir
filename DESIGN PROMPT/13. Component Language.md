# Mahaam — Component Language

## Shared principles

Components are calm, legible, tactile, and consistent. Use a focused library; do not invent a new component treatment for each section.

## Buttons

- **Primary:** Indigo fill, light text, refined shadow; label-first; 44–52px minimum height.
- **Secondary:** transparent or light surface with a clear border; strong text contrast.
- **Text link:** no pill container; directional RTL arrow on hover where appropriate.
- Avoid overly rounded “bubble” buttons and gradient fills.

## Inputs and forms

Forms should feel like a professional assessment, not lead capture.

- Persistent labels above fields
- Clear required / optional treatment
- Calm neutral surface, distinct focus state
- Helpful inline validation in Persian
- Multi-step progress uses descriptive labels, not only percentage
- Error text explains what to correct without blame

## Navigation

Use generous hit areas, clear active state, and an understated mega-menu for audiences and pathways if needed. Navigation must never obscure content on mobile.

## Accordion

Used for FAQ and secondary detail only. One clear question per row, readable answer, smooth height transition, and chevron reflecting RTL direction.

## Tags and labels

Use only for classification or contextual metadata. Avoid scattered pill tags as decoration.

## Feedback states

- Loading: quiet skeleton or progress cue, never a generic spinner as the only signal
- Success: concise Persian confirmation, clear next action
- Error: human explanation and recovery path
- Empty state: visual metaphor plus practical next step

## Accessibility

Every component needs keyboard focus, sufficient contrast, touch target of at least 44px, and a state understandable without color alone.
